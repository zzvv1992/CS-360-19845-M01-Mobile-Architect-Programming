# CS 360 Mobile Architecture and Programming

## Project Reflection

### Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

For this project, I developed an Inventory Tracker mobile application. The main goal of the app was to give users a simple way to keep track of items and their quantities. Users needed to be able to view their inventory, add and remove items, update quantities, and receive SMS notifications when inventory was running low. I wanted the app to be simple enough that someone could open it and quickly understand how to use it without needing instructions.

### What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?

The app needed screens for logging in, viewing inventory, managing inventory items, and controlling SMS notifications. I tried to keep the layout simple with clearly labeled buttons and information that was easy to read. One important part of the design was making SMS notifications optional so that users could deny the permission and still use the rest of the application. I think the design was successful because the main features were easy to find and users were not required to give unnecessary permissions to use the app.

### How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?

I approached the coding process by working on one feature at a time instead of trying to build the entire application at once. I started with the UI and then connected the different screens and features through the Java code. I also tested the app as I added features so that problems were easier to identify. This is something I can use in future projects because breaking a larger project into smaller pieces makes development and troubleshooting much more manageable.

### How did you test to ensure your code was functional? Why is this process important, and what did it reveal?

I tested the application using Android Studio and the Android emulator. I went through the different screens and tested the buttons, inventory features, and SMS permission options to make sure everything worked as expected. Testing is important because code can compile successfully but still not behave correctly when someone actually uses the application. Testing helped me find problems that I could correct before considering the application finished.

### Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?

One challenge was getting the different parts of the application to work together while also handling Android permissions correctly. The SMS feature was especially important because the application needed to request permission without becoming unusable if the user denied it. I had to make sure the app could continue functioning either way. Working through this challenge helped me better understand how Android applications handle permissions and user choices.

### In what specific component of your mobile app were you particularly successful in demonstrating your knowledge, skills, and experience?

I think I was particularly successful with the inventory management portion of the application. It brought together the UI design and the functionality of the app and demonstrated what I learned throughout the course. I was able to take the original UI design and turn it into a working application where users could interact with and manage their inventory. Overall, this project helped me become more comfortable with Android Studio and with the complete process of designing, developing, testing, and finalizing a mobile application.
